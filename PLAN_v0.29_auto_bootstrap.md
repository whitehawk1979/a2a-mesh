# A2A Mesh v0.29 — Auto-Bootstrap & Self-Healing Architecture

## Cél

Egy új agent telepítése után automatikusan:
1. Felismeri a platformját (macOS, Linux, Docker, HA addon, Windows)
2. Generál egy minimal config-ot ami nem zavar be a host rendszerbe
3. Csatlakozik a meglévő mesh-hez (PG discovery + P2P)
4. Ha nincs koordinátor → automatikus election
5. Ha van koordinátor → sima node-ként működik
6. Feladatokat a saját gépén végez (lokális végrehajtás)
7. Ha leáll és valaki javítja → lokális jegyzetet talál a változásokról

## 1. Auto-Bootstrap Wizard (`a2a init`)

### Parancs
```bash
python cli.py init --name <node_name> [--pg-host 192.168.1.30] [--platform auto]
```

### Funkciók
- **Platform detection**: macOS / Linux / Docker / HA-addon / Windows
- **IP detection**: LAN IP + Tailscale IP (ha van)
- **Port selection**: 8645 (P2P) + 8650 (health) — ha foglalt, következő szabad
- **PG discovery**: lekérdezi a mesh_nodes táblát, felismeri a meglévő node-okat
- **Config generation**: `mesh_config_<name>.yaml` — minimal, nem ír felül semmit
- **TLS**: self-signed cert generálás (ha nincs meglévő)
- **Coordinator check**: van-e aktív koordinátor a mesh-ben
- **Service install**: systemd / launchd / Docker / HA addon startup script

### Config template (minimal)
```yaml
mesh:
  node_name: <name>
  transport_priority: [p2p, pg_notify, http]
  capabilities: [a2a_messaging, file_transfer, p2p_transport, pg_transport, health_monitor, registry, dashboard]
  health_port: <auto>
  webhook_port: <auto>
  transports:
    pg_notify:
      host: <pg_host>
      port: 5432
      dbname: agent_memory
      user: nova
      password: <auto or prompt>
    p2p:
      enabled: true
      listen_host: 0.0.0.0
      listen_port: <auto>
      tls_enabled: true
      tls_cert: <auto-generated>
      tls_key: <auto-generated>
      tls_ca: <from mesh or auto-generated>
  discovery:
    min_target_peers: 2
    mdns:
      enabled: true
      service: _a2a._tcp
      port: <p2p_port>
    static:
      nodes: <auto-populated from PG>
```

### Platform-specifikus beállítások

| Platform | P2P bind | Port expose | Service |
|----------|----------|-------------|---------|
| macOS | 0.0.0.0 | direct | launchd |
| Linux | 0.0.0.0 | direct | systemd --user |
| Docker | 0.0.0.0 | host network or port mapping | container restart policy |
| HA addon | 0.0.0.0 | socat forward or addon config | HA supervisor |
| Windows | 0.0.0.0 | direct | Task Scheduler |

## 2. Coordinator Election (meglévő, kiegészítés)

### Jelenleg
- `core/election.py`: seniority-based (lowest short_addr)
- Coordinator heartbeat timeout: 7 min
- Failover: router with lowest short_addr takes over

### Kiegészítés
- **Bootstrap election**: új mesh (nincs node) → első node = coordinator
- **PG-based coordinator check**: `SELECT node_name FROM mesh.mesh_nodes WHERE role='coordinator' AND status='active' ORDER BY last_heartbeat DESC LIMIT 1`
- **Graceful reclaim**: eredeti koordinátor visszatérése → 30s várakozás → reclaim
- **Coordinator announcement**: PG NOTIFY `coordinator_change` channel

## 3. Lokális Feladatvégrehajtás

### Elv
- Minden agent a **saját gépén** végez feladatokat
- Delegáció = koordinátor kiosztja, worker végrehajtja lokálisan
- Nincs remote execution más gépen (kivéve: deploy, code review)

### Feladat típusok
| Típus | Hol fut | Példa |
|-------|---------|-------|
| `local_maintenance` | Saját gép | Gitea restart, service check, log rotation |
| `deploy` | Cél node | Git pull + restart + health check |
| `code_review` | Koordinátor | LLM elemzés peer node fájljairól |
| `monitoring` | Saját gép | Health metrics, disk space, CPU |
| `skill_sync` | Saját gép | PG → local skills/ dir |
| `config_sync` | Saját gép | PG → local config override |

## 4. Hiba-Napló Rendszer (Agent Recovery Notes)

### Concept
Amikor egy agent leáll és valaki (másik agent vagy Zsolt) javítja:
1. A javító agent egy `recovery_note`-ot ír a PG-be
2. Amikor a leállt agent újraindul, olvassa a recovery note-okat
3. Log-ba + dashboard-ra jelzi: "Recovery notes: X változás történt"

### PG séma
```sql
CREATE TABLE mesh.mesh_recovery_notes (
    id SERIAL PRIMARY KEY,
    target_node TEXT NOT NULL,        -- Agent aki leállt
    author TEXT NOT NULL,              -- Ki javította
    note TEXT NOT NULL,                -- Mi történt
    actions TEXT[],                    -- Mik voltak a lépések
    created_at TIMESTAMPTZ DEFAULT NOW(),
    read_at TIMESTAMPTZ NULL           -- Mikor olvasta az agent
);
```

### API
- `POST /api/recovery-note` — új jegyzet (author = javító agent)
- `GET /api/recovery-notes` — olvasatlan jegyzetek (target = self)
- `POST /api/recovery-notes/{id}/read` — megjelölés olvasottként

### Workflow
1. Nova észreveszi: Runa offline
2. Nova javítja (SSH deploy, restart)
3. Nova ír: `recovery_note(target='runa', author='nova', note='SSH deploy after crash, git reset --hard origin/main, restarted a2a-mesh')`
4. Runa felébred → olvassa a note-ot → log + dashboard
5. Runa jelzi: "Recovery: Nova deployed me after crash. Actions: git reset, restart"

## 5. Platform Detekció

```python
def detect_platform() -> str:
    """Detect the platform for auto-configuration."""
    import platform, os
    
    # Docker container
    if os.path.exists('/.dockerenv'):
        return 'docker'
    
    # HA addon (Home Assistant Supervisor)
    if os.environ.get('HASS_URL') or os.path.exists('/data/options.json'):
        return 'ha_addon'
    
    system = platform.system().lower()
    if system == 'darwin':
        return 'macos'
    elif system == 'linux':
        return 'linux'
    elif system == 'windows':
        return 'windows'
    return 'unknown'
```

## 7. Docker/HA P2P Fix (azonnali)

### Probléma
- Docker container-ben futó agent P2P portja nem elérhető kívülről
- Container IP (172.30.x.x) nem route-olható

### Megoldás
1. **Auto-detect Docker**: `/.dockerenv` → Docker mode
2. **Host IP report**: Docker mode-ban a node a host IP-jét reportálja a PG-ben (nem a container IP-jét)
3. **Port forward**: Auto-setup socat vagy iptables forward a host-on
4. **Config flag**: `p2p.advertise_host: 192.168.1.43` — a node ezt az IP-t reportálja

```yaml
# Docker/HA addon config kiegészítés
p2p:
  listen_host: 0.0.0.0
  listen_port: 8645
  advertise_host: 192.168.1.43  # Host IP (Docker case)
  advertise_port: 8645          # Host port (after forward)
```

## 8. Elvárások

- **Ne befolyásolja a host rendszert**: A2A mesh egy layer, nem módosítja a host config-ot
- **Auto-heal**: Ha egy agent leáll, mások javítják + recovery note-ot írnak
- **Platform független**: macOS, Linux, Docker, HA, Windows
- **Determinisztikus core**: Nincs LLM-függőség a core működésben
- **Lokális végrehajtás**: Minden agent a saját gépén dolgozik
